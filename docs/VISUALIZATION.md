# Visualization Design

## Design Philosophy

> 지식은 우주다. 각 지식은 별이고, 관계는 빛의 흐름이며, 카테고리는 은하다.
> 자주 쓰이는 지식은 밝게 빛나고, 잊혀진 지식은 어둠 속으로 사라진다.
> 충돌하는 지식은 붉게 경고하고, 빈 영역은 미지의 공간으로 남는다.

### 핵심 원칙
1. **Dark-mode-first** - 어두운 배경에 빛나는 노드 (우주/은하 메타포)
2. **데이터가 시각을 결정** - 리콜 빈도 = 밝기, 건강 상태 = 색상, 관계 = 빛의 흐름
3. **2D 기본 + 3D 탐험** - 작업할 땐 2D, 탐험할 땐 3D Galaxy 모드
4. **실시간 반영** - 지식이 추가/수정되면 그래프가 살아 움직임
5. **대규모 대응** - 수만 노드에서도 60fps 유지

## Graph View: 3가지 모드

### Mode 1: Constellation (은하 뷰) - 기본 모드

2D force-directed 그래프. 일상적 탐색과 작업에 사용.

```
┌──────────────────────────────────────────────────────────────┐
│ 배경: #0a0a1a (깊은 우주 남색)                                 │
│                                                              │
│          ╭─────╮                                             │
│         ╱ programming ╲    ← 은하 (카테고리 클러스터)          │
│        │  ◉ python     │   ← 별 (지식 노드, 크기=리콜빈도)    │
│        │    ╲          │                                     │
│        │  ○ git ──────────── ◎ devops  ← 엣지 = [[wikilink]] │
│        │         ╱     │        ╱                            │
│         ╲ ● api ╱     ╱    ◉ docker                          │
│          ╰─────╯     ╱                                       │
│                     ╱                                        │
│            ╭───────╯──╮                                      │
│           ╱  projects  ╲                                     │
│          │  ◈ my-app    │   ← ◈ = 충돌 있음 (빨간 테두리)     │
│          │  ○ blog      │                                    │
│           ╲            ╱                                     │
│            ╰──────────╯                                      │
│                                                              │
│  ◉ = 높은 리콜 (밝고 큼)    ○ = 낮은 리콜 (어둡고 작음)         │
│  ◈ = 충돌 pending          ◌ = stale (거의 안 보임)            │
└──────────────────────────────────────────────────────────────┘
```

#### 노드 시각 인코딩

| 속성 | 시각 매핑 | 범위 |
|------|----------|------|
| **크기** | 리콜 빈도 | 4px (리콜 0) → 24px (리콜 100+) |
| **밝기/광도** | 리콜 빈도 | 0.2 (어두움) → 1.0 (밝음) + bloom glow |
| **색상 (hue)** | 카테고리 | 카테고리별 고유 색상 (HSL 균등 분배) |
| **테두리** | 건강 상태 | 없음(정상), 빨간(충돌), 주황(만료임박), 점선(stale) |
| **형태** | 엔티티 타입 | ● concept, ■ project, ▲ person, ◆ event, ◇ reference |
| **펄스 애니메이션** | 최근 변경 | 최근 24시간 내 변경된 노드는 천천히 펄스 |

#### 엣지 시각 인코딩

| 속성 | 시각 매핑 |
|------|----------|
| **색상** | 소스 노드 색상 → 타겟 노드 색상 (그라디언트) |
| **투명도** | 0.08 (기본) → 0.6 (hover 시) - 시각 클러터 방지 |
| **두께** | 양방향 참조 시 더 두꺼움 |
| **파티클 흐름** | 최근 리콜된 경로를 따라 빛 입자가 흐름 |
| **빨간 점선** | 충돌 관계 표시 |

#### 클러스터 (카테고리) 시각화

```
카테고리 영역 표시 방법:
  - ConvexHull 또는 soft boundary로 카테고리 영역 표시
  - 반투명 색상 배경 (opacity 0.03~0.05)
  - 카테고리 이름 라벨 (큰 폰트, 낮은 opacity)
  - 카테고리 경계에 미세한 glow 효과
```

#### 인터랙션

| 동작 | 효과 |
|------|------|
| **호버** | 노드 강조 + 연결된 엣지/노드 하이라이트 + 나머지 fade out |
| **클릭** | 우측 패널에 지식 내용 표시 (MD 렌더링) |
| **더블클릭** | 해당 노드 중심으로 줌인 + 주변 컨텍스트 확대 |
| **우클릭** | 컨텍스트 메뉴 (편집, 아카이브, 관계 보기, 충돌 해결) |
| **드래그(노드)** | 노드 위치 이동 (물리 시뮬레이션 일시 정지) |
| **드래그(빈 공간)** | 화면 패닝 |
| **스크롤** | 줌 인/아웃 |
| **핀치** | 터치 줌 (모바일/태블릿) |

#### 필터 & 제어 패널

```
┌─────────────────────────────────────┐
│ 필터                                │
│ ┌─────────────────────────────────┐ │
│ │ 카테고리: [전체 ▼]              │ │
│ │ 상태:    ☑정상 ☑충돌 ☑stale ☐만료│ │
│ │ 기간:    [전체 ▼] / 최근 7일     │ │
│ │ 타입:    ☑concept ☑project ...  │ │
│ │ 리콜:    [───●────] 0~100+      │ │
│ └─────────────────────────────────┘ │
│                                     │
│ 표시                                │
│ ├ ☑ 라벨 표시                       │
│ ├ ☑ 파티클 흐름                     │
│ ├ ☑ 클러스터 배경                   │
│ └ ☐ 고아 노드 숨기기                │
│                                     │
│ 물리                                │
│ ├ 반발력:    [───●──] 0~200        │
```

### Mode 2: Galaxy (3D 은하 뷰) - 탐험 모드

3D force-directed + bloom 효과. 전체 지식 우주를 탐험할 때 사용.
Software Galaxies (anvaka/pm)와 3d-force-graph bloom 에서 영감.

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│                    ·  *                                       │
│            *  ·         ✦                                     │
│       ·          ·  ✦    ·   *                                │
│     ✦   programming    ·       ·                              │
│       ·    ✦  ·  *         projects                           │
│            ·       ·    *  ✦  ·                               │
│    *           ·       ·    ·                                 │
│         ·  personal  ·                                        │
│       *     ·  ✦        ·     *                               │
│           ·       ·                                           │
│                                                              │
│   [회전: 마우스 드래그] [줌: 스크롤] [클릭: 노드 포커스]       │
│   [2D 모드로 돌아가기]                                        │
└──────────────────────────────────────────────────────────────┘
```

#### 3D 전용 효과

- **Bloom post-processing**: 밝은 노드에 네온 glow (3d-force-graph bloom example 참고)
- **Depth of field**: 포커스 영역 외에는 살짝 블러
- **파티클 시스템**: 엣지를 따라 빛 입자가 흐름 (방향성 시각화)
- **카메라 애니메이션**: 노드 클릭 시 부드럽게 날아감 (fly-to)
- **별 배경**: 먼 배경에 미세한 별 효과 (ambient particles)
- **카테고리 = 은하계**: 같은 카테고리 노드들이 은하처럼 모여 있음
- **궤도 카메라**: 자동 천천히 회전 (idle 시)

#### 성능 고려
- 100개 미만: 3d-force-graph (WebGL + Three.js) - 풍부한 효과
- 100~10,000: 3d-force-graph 경량 모드 (bloom + 파티클만)
- 10,000+: cosmos.gl GPU 렌더링으로 전환 (2D 포인트 클라우드)

### Mode 3: Heatmap (열지도 뷰) - 분석 모드

지식의 사용 빈도와 건강 상태를 한눈에 파악.

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│  programming           personal           projects           │
│  ┌──────────────┐     ┌──────────────┐   ┌──────────────┐   │
│  │██████████    │     │████          │   │██████        │   │
│  │██████████    │     │████          │   │██████        │   │
│  │████████      │     │██            │   │████          │   │
│  │██████        │     │              │   │██            │   │
│  │████          │     │              │   │              │   │
│  └──────────────┘     └──────────────┘   └──────────────┘   │
│  47 files, 340 recalls 12 files, 89 rec  18 files, 156 rec  │
│                                                              │
│  devops                research            archive            │
│  ┌──────────────┐     ┌──────────────┐   ┌──────────────┐   │
│  │██            │     │░░░░░░░░░░░░░░│   │░░░░          │   │
│  │              │     │░░░░░░░░░░░░░░│   │              │   │
│  └──────────────┘     └──────────────┘   └──────────────┘   │
│  3 files, 8 recalls   0 files (GAP!)     5 files, 0 rec    │
│                                                              │
│  ████ = hot (자주 리콜)   ░░░░ = cold/gap (지식 부족)          │
│  색온도: 파란→보라→빨강→주황→노랑→흰색 (차가움→뜨거움)          │
└──────────────────────────────────────────────────────────────┘
```

Treemap 스타일. 각 사각형의:
- **면적** = 파일 수 또는 총 크기
- **색상** = 평균 리콜 빈도 (차가운 파랑 → 뜨거운 주황)
- **빈 영역/점선** = 지식 갭 (knowledge_status에서 보고된 빈 곳)
- **빨간 배지** = 미해결 충돌 수

지식 그래프가 시간에 따라 성장하는 과정을 애니메이션으로 재생.
Gource (소프트웨어 저장소 역사 시각화) 에서 영감.

```
│  │   Day 1: 첫 노드 등장                                  │  │
│  │   Day 7: 클러스터 형성 시작                              │  │
│  │   Day 30: 크로스 레퍼런스 활발                           │  │
│  │   Day 60: 갈라진 카테고리 재편                           │  │
│  │   Today: 현재 상태                                      │  │
│  │                                                        │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                              │
│  현재 날짜: 2026-03-15                                       │
│  총 노드: 87 | 엣지: 134 | 카테고리: 6                       │

```

동작:
- 재생 버튼 누르면 Day 1부터 노드가 하나씩 나타남
- 새 노드 등장 시 ripple 애니메이션
- 엣지가 생길 때 빛 줄기가 뻗어나감
- 충돌 발생 시 빨간 번개 효과
- 카테고리가 형성되면 soft boundary가 서서히 나타남
- 타임라인 슬라이더로 특정 시점으로 점프 가능

## 기술 스택 결정

### 그래프 렌더링 라이브러리 조합

조사 결과를 바탕으로 한 추천 조합:

| 모드 | 라이브러리 | 이유 |
|------|-----------|------|
| **Constellation (2D)** | **Sigma.js + graphology** | WebGL 렌더링, 수만 노드 대응, 커스텀 노드 프로그램으로 glow/shape 가능 |
| **Galaxy (3D)** | **3d-force-graph** | bloom + 파티클 + fly-to 내장, 가장 인상적인 3D, MIT 라이선스 |
| **Heatmap** | **D3.js treemap** | treemap 구현의 표준, 완전한 커스터마이징 |
| **Timeline 차트** | **D3.js + custom** | 타임라인/캘린더 히트맵 구현에 최적 |
| **통계 차트** | **Chart.js 또는 Recharts** | 간단한 차트(area, bar, donut)에 충분 |
| **초대규모 폴백** | **cosmos.gl** | 10만+ 노드 시 GPU 렌더링으로 전환 |

### 대안 조합

- **AntV G6**: 2D만 필요하다면 올인원 솔루션 (레이아웃+렌더링+인터랙션)
- **Cytoscape.js**: 레이아웃 알고리즘이 가장 풍부 (15+ 알고리즘)
- **react-force-graph**: React 앱이라면 2D/3D/VR/AR 모두 지원

### 디자인 토큰 (색상 팔레트)

```css
/* 배경 */
--bg-deep:     #0a0a1a;    /* 메인 배경 (깊은 우주) */
```

## 독창적 시각 요소

### 1. Knowledge Pulse (지식 맥박)

노드가 "살아있는" 느낌. 최근 리콜/수정된 노드는 심장박동처럼 미세하게 펄스.

```
리콜 직후:        빠른 펄스 (1초에 2회, 5초간)
최근 24시간 내:   느린 펄스 (3초에 1회)
24시간 이후:      정지 (정적 밝기)
```

### 2. Recall Flow (리콜 흐름)

가장 최근 knowledge_search 결과 경로를 따라 빛 입자가 흐름.
"방금 이 지식을 찾아갔다"는 것을 시각적으로 보여줌.

```
검색: "Python 데코레이터"
  → _router.md ──빛──→ programming/_index.md ──빛──→ python-advanced.md
     경로를 따라 파티클이 0.5초간 흘러감
```

### 3. Conflict Lightning (충돌 번개)

충돌하는 두 노드 사이에 빨간 번개 효과.
해결되면 번개가 사라지고 초록 체크마크 ripple.

### 4. Growth Ripple (성장 파문)

새 지식이 추가될 때 해당 위치에서 원형 파문이 퍼져나감.
새 연결(엣지)이 생길 때 빛 줄기가 뻗어나감.

### 5. Dark Nebula (어둠 성운)

knowledge_status에서 보고된 knowledge_gaps 영역.
그래프 상에서 해당 카테고리 주변에 어둡고 흐릿한 영역으로 표시.
"여기에 지식이 부족하다"는 것을 시각적으로 암시.

### 6. Star Trail (별의 궤적)

성장 애니메이션에서 노드가 이동한 경로를 잔상으로 표시.
카테고리 재편 시 노드가 한 클러스터에서 다른 클러스터로 이동하는 궤적.

## Structure View: MD 구조 시각화 (도서관 분류 체계 착안)

도서관학에서 가져온 정보 구조화 원리를 시각화에 적용한다.
도서관 UI를 만드는 게 아니라, **계층 분류/색인/상호참조의 원리**를 차용.

### 도서관에서 가져온 원리

```
도서관 원리                        시각화 적용
────────────────────────────────────────────────────
분류 체계 (듀이 십진법)    →  카테고리 클러스터를 Treemap으로
색인 카드 (메타데이터)     →  frontmatter를 필터/정렬 축으로
서가 배치 (관련=가까이)    →  같은 카테고리 = 시각적 인접
상호 참조 ("~도 참고")    →  [[wikilink]] 엣지 강조
사서 (질문→안내)          →  검색 결과 하이라이트 경로
대출 빈도 → 인기 서가     →  리콜 빈도 → 노드 크기/밝기
빈 서가 = 수집 필요       →  지식 갭 = 빈 영역 표시
```

### Mode 4: Structure (구조 뷰)

그래프 뷰의 4번째 모드. wiki/ 디렉토리 계층을 Treemap으로 시각화.
"뭐가 있고, 얼마나 있고, 뭐가 비었는지"를 한눈에.

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│  ┌──────────────────────────┐ ┌──────────────┐ ┌─────────┐ │
│  │                          │ │              │ │         │ │
│  │      programming         │ │   projects   │ │personal │ │
│  │                          │ │              │ │         │ │
│  │  ┌────────┐ ┌──────┐    │ │ ┌──────┐     │ │ ┌─────┐ │ │
│  │  │python  │ │ api  │    │ │ │my-app│     │ │ │prefs│ │ │
│  │  │████████│ │██████│    │ │ │██████│     │ │ │█████│ │ │
│  │  │        │ │      │    │ │ │      │     │ │ └─────┘ │ │
│  │  │        │ └──────┘    │ │ └──────┘     │ │         │ │
│  │  │        │ ┌────┐┌───┐ │ │ ┌────┐ ┌──┐  │ │         │ │
│  │  │        │ │git ││ts │ │ │ │blog│ │cl│  │ │         │ │
│  │  └────────┘ │▓▓▓ ││▓  │ │ │ │▓▓  │ │░ │  │ │         │ │
│  │             └────┘└───┘ │ │ └────┘ └──┘  │ │         │ │
│  └──────────────────────────┘ └──────────────┘ └─────────┘ │
│                                                              │
│  ┌───────┐ ┌─────────────────────────────────┐               │
│  │devops │ │░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░│               │
│  │ ┌───┐ │ │                                 │               │
│  │ │░░ │ │ │         research (EMPTY)        │               │
│  │ └───┘ │ │            지식 갭               │               │
│  └───────┘ └─────────────────────────────────┘               │
│                                                              │
│  면적 = 파일 수   색 채도 = 평균 리콜 빈도                      │
│  ████ hot  ▓▓▓ warm  ░░░ cold/empty                          │
└──────────────────────────────────────────────────────────────┘
```

시각 인코딩:
- **영역 면적** = 카테고리 내 파일 수 (또는 총 크기)
- **영역 내 사각형** = 개별 파일, 크기 = 파일 크기
- **색 채도** = 평균 리콜 빈도 (뜨거움 → 차가움)
- **점선 빈 영역** = 지식 갭 (카테고리는 있지만 내용 부족)
- **빨간 점** = 충돌 있는 파일
- 클릭 → 해당 파일을 Explorer 뷰에서 열기
- 호버 → 파일명, 리콜 수, 태그, 마지막 수정일 툴팁

Treemap은 "공간 효율"이 핵심. 한 화면에 수백 파일의 크기/빈도/갭을 동시에 보여줄 수 있다.

### 구조 뷰 + 그래프 뷰 전환

같은 데이터를 다른 관점으로:

| | 구조 뷰 (Treemap) | 그래프 뷰 (Force-directed) |
|---|---|---|
| 보여주는 것 | 계층, 크기, 밀도, 갭 | 관계, 연결, 허브 |
| 질문 | "뭐가 있고 뭐가 없나?" | "뭐가 연결되었나?" |
| 레이아웃 | 공간 채움 (빈 곳 = 갭) | 힘 기반 (가까움 = 관련) |

두 뷰 사이를 부드럽게 전환하는 모핑 애니메이션이 있으면 좋다.
Treemap의 사각형이 그래프의 노드로 변환되며 재배치되는 트랜지션.

## 구현 전략

### 핵심 결정: 단일 렌더링 엔진

라이브러리를 모드별로 4개 쓰지 않는다.
**react-force-graph-3d (Three.js) 하나를 기반으로, 노드 좌표만 바꿔서 모든 뷰를 표현한다.**

```
Sigma.js (2D) + 3d-force-graph (3D) + D3.js (Treemap) + Chart.js (통계)
→ 렌더러 4개, 데이터 포맷 4개, 스타일 통일 불가

대신:

react-force-graph-3d (Three.js) 하나로:
  - Constellation = 카메라 정면 고정 (z=0 평면)
  - Galaxy        = 카메라 자유 회전
  - Heatmap       = 노드를 grid 좌표로 재배치
  - Structure     = 노드를 treemap 좌표로 재배치
  - 모드 전환     = 노드 위치 tween 애니메이션
```

### 모드 전환의 핵심 트릭

모든 노드에 4가지 좌표를 사전 계산:

```javascript
node.positions = {
  constellation: { x, y, z: 0 },    // force-directed 2D
  galaxy:        { x, y, z },        // force-directed 3D
  heatmap:       { x, y, z: 0 },    // 카테고리별 grid
  structure:     { x, y, z: 0 },    // treemap 좌표
}
```

모드 전환 시 현재 좌표 → 목표 좌표로 tween.
사용자에게는 "노드들이 재배치되며 다른 관점을 보여주는" 경험.

### 데이터 흐름

```
Python MCP 서버 (FastAPI)
  │
  │ GET /api/graph
  ▼
{
  nodes: [{ id, label, category, recalls, size, health, entity_type }],
  edges: [{ source, target, type }],
  clusters: [{ name, color, node_ids }],
  stats: { total_facts, conflicts_pending, ... }
}
  │
  ▼
React App (react-force-graph-3d)
  ├ 좌표 계산 (force / grid / treemap)
  ├ 모드별 카메라/레이아웃 적용
  ├ Three.js 효과 (bloom, 파티클, 펄스)
  └ 사이드 패널 (상세, 필터, 통계)
```

### 단계별 구현

```
Phase A: 기본 그래프
  react-force-graph-3d로 노드+엣지 렌더링
  카메라 고정(2D) ↔ 자유(3D) 전환
  노드 크기/색상 = 리콜빈도/카테고리
  클릭/호버 인터랙션
  → Constellation + Galaxy 완성

Phase B: 시각 효과
  Three.js UnrealBloomPass (glow)
  파티클 흐름 (엣지 따라)
  펄스 애니메이션, 클러스터 배경
  다크 배경 + 네온 팔레트
  → 기존 코드 위에 레이어 추가

Phase C: Heatmap + Structure
  grid/treemap 좌표 계산 로직 추가
  모드 전환 시 tween으로 노드 재배치
  같은 씬, 같은 렌더러
  → 4가지 모드 완성

Phase D: 통계 + 타임라인
  그래프 캔버스 밖 별도 패널
  Recharts (가벼운 차트)
  커스텀 타임라인 컴포넌트
  → 그래프 렌더러와 독립

Phase E: 대규모 최적화
  LOD (줌 레벨별 디테일)
  클러스터 접기/펼치기
  10,000+ 시 파티클 모드
```

### 기술 스택

```
렌더링:    react-force-graph-3d (Three.js 기반)
효과:      Three.js post-processing (Bloom, FXAA)
애니메이션: GSAP 또는 @tweenjs/tween.js
프론트:    React + TypeScript (Vite)
차트:      Recharts
스타일:    Tailwind CSS (다크 모드)
통신:      REST API (Python FastAPI → React)
```
